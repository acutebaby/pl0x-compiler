========================================================
 Windows 下的编译与运行  （第 5 组 PL/0 编译器）
========================================================

【一、最简单的用法】

  1. 打开文件夹  pl0x_deliver
  2. 双击  run.bat
  3. 按提示输入用例编号（例如输入 10，或 t10），回车
  4. 看完结果按任意键关闭窗口

  也可以把某个 .pl0 文件直接拖到 run.bat 图标上运行。


【二、为什么要用 run.bat】

  Windows 命令行默认代码页是 936（GBK），而 pl0x.exe 输出的中文
  是 UTF-8 编码。直接在 cmd/PowerShell 里跑 pl0x.exe 会看到
  “婧愮▼搴?” 这样的乱码。

  run.bat 已经替你做了三件事：
    - chcp 65001   把控制台切到 UTF-8，中文正常显示
    - 检查 exe     没有的话自动调用 build.bat 编译
    - pause        程序结束后停住，窗口不会一闪而过

  如果你想手动敲命令，必须先切代码页：

      chcp 65001
      src\pl0x.exe cases\t10.pl0

  运行前务必先 cd 到 pl0x_deliver 目录，并且保证路径里没有
  中文——用相对路径 cases\t10.pl0 最省事。


【三、重新编译】

  双击  build.bat

  它会自动按顺序尝试：
    1) gcc（MinGW-w64），如果装了的话
    2) Visual Studio 的 cl.exe，直接定位 MSVC 与 Windows SDK，
       不需要先开“开发者命令提示”

  本机已装 Visual Studio 2022 Community，编译通过，
  生成 src\pl0x.exe。


【四、输出文件在哪】

  run.bat 会在  _out\<用例名>\  下生成四个文件：

      fa.tmp    目标代码（P-代码）清单
      fas.tmp   名字表清单
      fa2.tmp   运行结果
      f1.tmp    源程序清单与错误信息

  以及 run.bat 自己保存的完整控制台回显。

  拿这四个文件和  run\<用例名>\  下的同名文件对比，
  内容一致即说明复现成功。


【五、注意事项】

  1) t4 需要键盘输入：
     第 1 行输入元素个数（如 5），
     第 2 行输入对应个数的整数（如 3 17 9 42 8）。

  2) run\ 下的参考文件是 Linux 上生成的，换行符是 LF；
     Windows 生成的是 CRLF。文件大小会差一点，
     用文本对比工具时忽略换行差异即可，内容完全相同。

  3) 12 个用例 t1~t12 在本机（Windows 11 + MSVC 14.44）
     全部编译运行通过，运行结果与 run\ 下的记录逐字一致。


【六、常见故障】

  “终端打不开 / 闪一下就没”
      → 双击 run.bat，不要直接双击 src\pl0x.exe
        （exe 运行完立即退出，窗口自然一闪而过）

  PowerShell 提示“禁止运行脚本”
      → 不要用 .ps1；本目录给的是 .bat，不受执行策略限制。
        如果确实要放开，可在 PowerShell 里执行：
        Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

  中文乱码
      → 确认是通过 run.bat 启动（内部已 chcp 65001）。
        若在 VS Code 终端里手动运行，先执行 chcp 65001 。

  “无法打开源程序文件”
      → 路径里有中文或空格导致。cd 到 pl0x_deliver 目录后
        使用相对路径 cases\t10.pl0。
